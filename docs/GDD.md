# PROJECT ROY: Off the Grid — מסמך אפיון

סימולטור חיים on-chain בהשראת **"Roy: A Life Well Lived"** (ריק ומורטי, עונה 2 פרק 2)
ובהשראת מבנה הריצה של **Legionnaire.xyz**.

---

## 1. Game Overview

| | |
|---|---|
| **ז'אנר** | On-Chain Rogue-lite / Life Simulation / High-Stakes Strategy |
| **פלטפורמה** | דפדפן, mobile-first, RTL עברית |
| **אורך ריצה** | 6–12 דקות (10–28 פרקים, תלוי בתדירות ההחלטות) |
| **סטאק** | HTML + CSS + Vanilla JS (ES modules). אפס תלויות runtime |

### Core Loop

1. **Mint** — תשלום `10 $TICKET`, יצירת Roy ID עם תכונות שנגזרות מה־seed.
2. **Decide** — כל פרק מציג אירוע ו־2–3 בחירות תחת שעון עצר.
3. **Balance** — איזון בין בריאות, שפיות, קריירה והון.
4. **Finalize** — permadeath, צריבת Soulbound, כניסה ל־Leaderboard, הורשת תכונה לדור הבא.

## 3. משאבים ותכונות

**ארבעה משאבים.** בריאות / שפיות / קריירה בסולם 0–100; הון ב־$ ללא תקרה, יכול להיות שלילי.

- בריאות `0` → סיום `health`
- שפיות `0` → סיום `sanity` (ההתעוררות)
- הון שלילי מתחת ל־`-40,000` → מפעיל את משבר החוב
- גיל `94` → סיום `oldage`

**ארבע תכונות** (2–9, נגזרות מה־seed):

| תכונה | השפעה |
|---|---|
| חוסן | מרכך נזק לבריאות (`×(1-(t-5)·0.05)`) |
| כריזמה | מגביר עלייה בקריירה ובהכנסות |
| מזל | מטה את ההגרלה לכיוון התוצאות הטובות (`r^(1+(luck-5)·0.09)`) |
| טירוף | עמידות לאובדן שפיות + בונוס למכפיל בבחירות degen |

## 4. Pacing — תדירות החלטות

בהשראת בורר תדירות ההחלטות של Legionnaire:

| הגדרה | מה קורה | פידבק בממשק |
|---|---|---|
| כל פרק | כל צומת עובר דרך השחקן | "שליטה מלאה — ריצה ארוכה" |
| 2 פרקים | פרק אחד נפתר ע"י המנוע בין החלטה להחלטה | **"חוויה מאוזנת"** (ברירת מחדל) |
| 3 פרקים | שני פרקים אוטומטיים | "ריצה מהירה, פחות שליטה" |

הפרקים האוטומטיים נפתרים ע"י `autoPick()` עם הטיה לפי מסלול, ומוצגים לשחקן כ־**FAST-FORWARD digest**
לפני ההחלטה הבאה. באירועי משבר ההטיה משתטחת — אחרת רוב הריצות היו נגמרות באבחנה הראשונה.

## 5. ניקוד — "Life Well Lived"

```
base = גיל×6 + שיא_קריירה×4.5 + הון/800 + שפיות×2.2 + בריאות×1.1
     + אבני_דרך×26 + ניקוד_החלטות×0.55 − קנסות
total = base × multiplier
```

המכפיל מתחיל ב־1.0 (מורטי) או 1.6 (ריק) וגדל עם כל בחירת סיכון.

**דירוגים:** `S ≥ 4000` · `A ≥ 2800` · `B ≥ 1800` · `C ≥ 1000` · `D`

```
src/state.js        מצב ריצה, תכונות, פריטים, החלת אפקטים
src/events.js       חפיסת האירועים (48 אירועים + 4 משברים + סיומים)
src/engine.js       בחירת אירוע, הגרלת תוצאה, auto-resolve, הזדקנות, סיומים

src/chain.js        MockChainAdapter — ארנק, $TICKET, tx log, SBT, leaderboard
src/collection.js   הישגים
src/ui.js           רינדור
src/main.js         בקר — לולאת הפרקים, שעון עצר, הצבעת נחיל
contracts/RoyRun.sol   חוזה ייחוס ל־Base/Arbitrum
```

### Provably fair

כל הגרלה נגזרת מ־`seed ‖ chapter ‖ salt` דרך `sfc32`. אותו seed = אותה ריצה בדיוק,
וה־receipt של כל הטלה מוצג ב־on-chain log. בפרודקשן ה־`digest()` מוחלף ב־`keccak256`
ו־commit-reveal מול VRF.

### Tokenomics

- `$TICKET` — דמי כניסה של 10 לריצה, נכנסים למאגר הפרסים (sink).
- **חלוקת מאגר:** `S → 50%` · `A → 30%` · `B → 15%` · `C → 5%`.
- **Dynamic metadata** — התכונות והסטטוס של ה־NFT מתעדכנים לאורך הריצה
  (`Carpet Salesman` מול `Outlaw`), עד לשריפה בסיום.

## 8. מה מדומה בפרוטוטייפ

שכבת הבלוקצ'יין רצה מול `MockChainAdapter` ב־localStorage: ארנק, יתרות, טרנזקציות,
מאגר פרסים, Soulbound ולוח תוצאות. הממשק זהה למה שיחובר ל־provider אמיתי,
והחוזה ב־`contracts/RoyRun.sol` מגדיר את הצד השני.

**Roadmap להעברה ל־chain אמיתי:**

1. `EthersChainAdapter` שמממש את אותן מתודות מול `RoyRun.sol` על Base Sepolia.
2. Commit-reveal אמיתי ל־seed + VRF להטלות.
3. אינדוקסר (Ponder/Subgraph) ללוח תוצאות עונתי במקום localStorage.
4. חתימת session key כדי לא לבקש חתימה על כל פרק.
